## 在验证中修正的问题

1. 新版 markdown-it 更换浏览器发布文件路径：资源准备脚本改为真实 UMD 路径，并锁定安装版本。
2. MathJax 默认扩展将未知命令作为红色文字处理：显式关闭 noundefined / autoload / require，恢复可识别的错误提示；只使用本地已准备扩展。
3. MathJax 动态样式不全在 style.textContent 中：使用正式 cssText API，并先将样式连接到文档后提取。
4. PDF 超时响应先于任务清理：清理进程、释放锁后再发送响应。
5. 慢文件导入会在失效后覆盖新编辑内容：局部准备全部结果，核对任务版本后一次提交界面状态。
6. 切换 PDF 模式导致请求撞上前一个任务：前端串行请求并丢弃失效结果，不用中断客户端等待来冒充服务端任务取消。
7. 文字层 cqw 缺少页面容器：增加页面的尺寸查询容器，使字体与图像同比缩放。
8. Windows 默认 HTTP socket 可重复绑定端口：使用独占 socket，并增加真实重复启动回归测试。

## 实现决策与边界

- 使用用户批准的新 Folio 项目目录与功能分支，没有另建工作树；同级 BikeCast 没有修改。
- Windows 沙箱对自动测试服务进程树清理存在限制，验证时显式管理测试服务；Playwright 可以复用测试端口。修改 Python 后应重启测试服务，避免旧模块驻留。
- 前端 PDF 请求使用串行队列，替代原计划的 AbortController；取消客户端等待不会终止服务端解析，串行队列能可靠实现最新模式生效。代价是新 PDF 操作需要等待当前任务结束或超时。
- 增加像素总量限制，避免正常文件体积上限之内的巨大页面引发无限制渲染内存占用。
- 原始模板图、示例参数和 PDF 均为项目生成内容。加密输入为本地生成测试文件，不包含用户文件。
- 尚未验证用户实际 PDF；数学 OCR、通用 OCR、自动外链图片下载、商业字体嵌入不在首版范围内。
- 已验证现有环境内的完整安装脚本重放；没有声称在全新 Windows 机器或所有 Python / 浏览器版本上验证过安装。
