## 原生验收与边界

原生验收使用本任务专用 FolioSmoke 模拟器，未操作其他 AVD 或用户设备。遇到 System UI ANR、旧选择器任务残留时保留失败日志，并使 runner 正确拒绝 shell 0 假阳性；这些失败不是保存功能的已确认缺陷。测试入口清理自己的 Activity 任务，并初始化专用测试草稿；使用真实 touch 打开文件选择器。

最终默认原生 runner 整体 exit 0：日志同时含本轮 `SAF_SAVE PASS`、`SAF_CANCEL PASS`、取消后再次 `SAF_SAVE PASS`、`PASS: Folio RuntimeSmoke` 和 `INSTRUMENTATION_CODE: -1`。两个保存文件均从 Downloads 拉回，逐字节核对为 16 字节 UTF-8 的 `Folio SAF 测试`。证据在本机 `artifacts/android-audit-fix/instrumentation.log`、`saved-smoke.html` 和 `saved-retry.html`。

可选 `-IncludePdfImport` **仍未通过**：已真实触摸打开 DocumentsUI，样例 PDF 已索引并可见，但自动选择文件卡片后未稳定返回应用；最后失败为 `PDF picker did not return after selection`。失败日志 `instrumentation-optional-pdf-unconfirmed.log` 保留，不能据此认定生产导入有缺陷，也不能宣称该导入端到端已成功。

最终开发签名 APK 的 `assembleRelease` / `assembleReleaseAndroidTest` 成功；本轮原生 runner 未执行完整 `lintRelease`。构建、Lint、签名检查与原生运行分开判断。实体手机、API 26 / WebView 120、厂商文件提供器与低内存回收仍未覆盖。

仪器测试会通过恢复界面**放弃专用测试 AVD 中已有草稿**以初始化场景，不使用 `pm clear`；这并非无副作用检查。不要用于日常设备或存有重要草稿的模拟器。

## 最可能失败的三个点

1. 一个异常方向字形会让该页回退并失去选择层，复制能力降低；以保留内容正确性和原页外观为优先，诊断中说明原因。
2. 超长 Markdown 仍同步解析，较慢手机可能出现长任务；本次去掉已证实的平方级查询，没有声称实现可中断 worker 解析。
3. Android 原生测试依赖模拟器系统窗口与文件提供器；用明确任务/窗口等待、超时和日志区分脚本、系统与产品问题，不能据此推定所有真机行为相同。

已有 `v1.2.0-beta.1` 附件是历史发行，不在此轮测试中静默覆盖。修复代码、原生测试产物和 Windows 冻结程序验收分别追踪。
