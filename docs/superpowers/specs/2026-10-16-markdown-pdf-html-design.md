# 墨页 Folio：Markdown / PDF 转 HTML 设计规格

日期：2026-10-16

状态：对话设计已确认；本规格待用户审阅。尚未开始产品实现。

项目位置：`D:\PyorC\Folio`

## 1. 用户目标与已确认的范围

用户需要一个本机运行、通过浏览器操作的 Markdown / PDF 转 HTML 工具。成功标准是公式专业、排版美观、表格与图片尽量完整，字体尽量保留或合理改善。文件在本机处理。

用户已确认采用 Markdown 专业排版与 PDF 双模式方案：保真模式优先保留原页外观；阅读模式尝试生成可重排的 HTML。用户没有要求 PDF 公式自动恢复为可编辑 LaTeX，首版不包含数学 OCR、通用 OCR、云端模型或收费 API。

以下是可在实现时调整的工程默认值，不冒充用户明确提出的要求：产品名为“墨页 Folio”；首先支持 Windows、现代 Edge / Chrome；单次处理一份主文档和其关联图片；默认端口 8765，可配置，冲突时显示清楚的启动错误；提供三个主题和单文件 HTML 导出。

## 2. 方案选择与理由

| 方案 | 优点 | 局限 | 决定 |
| --- | --- | --- | --- |
| 纯浏览器处理 | 服务简单，文件无需提交给本地服务 | PDF 表格与复杂版面重建能力有限 | Markdown 在浏览器内处理，PDF 不采用此方案 |
| 本地 Python 服务 + 浏览器界面 | 可以利用成熟 PDF 渲染、字符和表格提取库，便于双击启动 | 首次使用需要安装本地依赖 | 采用 |
| Electron 桌面程序 | 可以封装为完整桌面体验 | 安装包和维护成本较大，对首版转换质量没有直接帮助 | 首版不采用 |

界面使用原生 JavaScript 与 CSS，避免引入与文档转换无关的前端框架。Python 提供本地静态资源和 PDF 转换接口。Node.js / npm 仅用于安装、准备浏览器依赖，不作为日常运行的第二个服务。

## 3. 用户流程与界面

1. 用户运行安装脚本完成首次准备，再双击启动脚本；默认打开 `http://127.0.0.1:8765`。
2. 用户拖入或选择 `.md`、`.markdown`、`.pdf`；也可以粘贴 Markdown，或加载内置示例。
3. Markdown 可同时导入图片文件或整个资源文件夹；保留相对路径用于解析引用。
4. 左侧显示文件、模式、主题和排版选项；中央显示 Markdown 编辑器或 PDF 原页；右侧显示结果。窄窗口通过标签切换原文与预览。
5. 转换过程中显示状态，发生错误时保留现有输入。资源缺失、公式错误和 PDF 回退分别给出具体提示。
6. 预览完成后下载单个 `.html` 文件；按钮只在最新输入转换完成时可用。

视觉方向：浅色工作区、清晰的工具栏、墨绿强调色、纸张式预览。优先保证文档本身易读；图标附有文字或可访问名称；表单可以键盘操作；状态通过可读文本呈现。

## 4. Markdown 转换

### 4.1 文档结构

支持标题、段落、引用、有序与无序列表、链接、分隔线、代码块、行内代码、表格、脚注和删除线。生成稳定且去重的标题锚点与目录。代码块使用 highlight.js；未知语言保留为普通代码。

Markdown 使用 markdown-it 及脚注插件解析。内嵌 HTML 仅允许经过 DOMPurify 清理后的静态内容，例如表格、上下标和图片；移除脚本、事件处理器、活动嵌入、危险 URL 和导入样式。转换器不执行输入文档中的代码。

### 4.2 数学公式

支持 `$...$`、`$$...$$`、`\(...\)`、`\[...\]` 四种分隔符。数学片段在 Markdown 解释反斜杠、下划线等字符前被识别，代码块和行内代码不作为公式处理。

单美元行内公式不跨行，开始符后与结束符前不可为空白，结束符后不可紧接数字；反斜杠转义的美元保留为文字。因此常见的 `$20 和 $30` 不作为一段公式，`$x + y$` 可以排版。双美元与方括号分隔的独立公式允许跨行；不完整的分隔符保留原文并提示，不吞掉后续正文。

使用本地 MathJax 4 的 TeX 输入与 SVG 输出，支持常用 AMS 数学结构、矩阵、分段函数、多行对齐、显式编号与标签。默认不为每个独立公式自动编号。数学解析出错时显示原式和可定位的错误提示，不用近似公式静默替换。

预览与导出共享同一份已完成公式排版的内容；导出不重新解析 Markdown。SVG 使用局部或无共享字体缓存，避免复制后的公式引用丢失。保留公式源码作为可访问说明与复制依据；SVG 外观并不意味着字符可直接按普通文本复制。

### 4.3 表格、字体、图片

表格保留单元格、对齐和安全的合并单元格信息，增加表头与适当的留白；宽表在窄屏横向滚动，打印样式降低被裁切的风险。

三个主题为“学术论文、现代阅读、简洁报告”。可调整正文字体族、字号、行距和最大内容宽度；采用包含中文字体的系统字体回退。首版不自动分发或嵌入用户系统中的商业字体，因此跨电脑的正文外观允许合理差异。

导入的 PNG、JPEG、WebP、GIF 与经过清理的 SVG 图片转换为内嵌资源，保持纵横比，不主动放大低分辨率图片。相对路径以主文件所在的导入目录为基准，支持中文、空格和常见 URL 编码。路径匹配不明确时提示用户，不随意使用同名图片替代。

默认不自动下载网络图片，不发送任何包含文档内容的外部请求。外链图片显示未内嵌提示，用户可以导入对应本地图片。自包含导出要求所有图片引用已经内嵌；如仍有缺失资源，阻止“完整离线导出”并指出缺失项，用户可以先补图或明确选择带缺失标记的导出。

## 5. PDF 双模式

PDF 转换在 Python 子进程中完成，使用 pypdfium2 渲染、pdfplumber 提取字符和表格。具体依赖版本在安装阶段核实兼容性后锁定，并保留必要的第三方许可说明。

### 5.1 保真模式

每页以可配置分辨率渲染为内嵌 PNG（默认 144 DPI，可选 96 / 192 DPI），通过 HTML 页面容器保留页面纵横比和页间距。公式、字体形状、图片和表格外观来自 PDF 渲染结果，不重新推断公式源码。

对于可提取文字的页面，添加按坐标定位的透明文字层，尽量支持搜索和选择；这层文字不承担视觉排版。文字层需使用页面实际宽高与浏览器统一缩放，测试旋转页和不同页面尺寸。对于无法可靠定位的页关闭文字层并提示，避免复制出明显错误的定位内容。

保真结果是具有页面视觉层的 HTML，而非逐个还原出来的原生 HTML 表格、可编辑公式或无限缩放的矢量页面。高倍放大仍受导出分辨率限制，界面明确说明此点。

### 5.2 阅读模式

对于有可用文字层的简单页面，依据字符位置、字号、字体特征和阅读顺序组织标题与段落，提取可信的有线表格，并把能定位的图片裁切后内嵌。识别属于启发式推断，输出中保留页号和警告，不声称与原页完全等价。

每页结果提供“查看原页”的折叠区，包含同页保真图，便于核对没有被重建的图形与内容。对于扫描页、复杂分栏、明显的数学符号布局或无法安全重排的页面，整页回退到保真图，并解释回退原因。首版不声称能够可靠地逐式定位或识别任意 PDF 公式。

没有可提取文字的扫描件仍可通过保真模式转换。密码保护的 PDF 首版显示明确错误并请用户先使用自己有权处理的解密副本；不实现密码破解，也不记录密码。

## 6. 离线导出契约

导出内容包含完整 HTML5 文档、UTF-8 元数据、标题、内嵌主题 CSS、正文、公式 SVG、图片 data URL 与打印样式。导出的文档无需本地服务、外部 CDN、额外图片目录或 MathJax 脚本即可展示已排版内容。

普通网页链接允许保留，因为它们是用户主动点击的导航，不是显示文档所必需的依赖。默认移除其他可自动加载的远程资源。目录使用文档内部锚点，PDF 原页使用原生 `details` 元素，保证导出后可以无脚本工作。

导出文件名从原文件名派生，去除文件系统非法字符；下载不覆盖源文档。预览位于受限 iframe 中，禁用输入文档脚本；导出 HTML 中也不包含源文档的可执行脚本。

## 7. 模块边界与接口

| 模块 | 责任 | 输入 / 输出 |
| --- | --- | --- |
| 本地服务 | 启动、静态资源、输入限制、PDF 子进程调度 | 静态页面；`GET /api/health`；`POST /api/pdf` |
| PDF 转换器 | PDF 渲染、文字层、阅读模式重建与回退 | PDF 字节和模式 / DPI → 页面 HTML、元数据、警告 |
| Markdown 转换器 | 语法、代码高亮、公式保护与文档结构 | Markdown 和资源映射 → 清理后的内容、目录、诊断 |
| 公式模块 | 本地 MathJax 排版、等待完成、错误收集 | TeX 片段 → 自包含 SVG 与源码说明 |
| 资源模块 | 路径规范化、图片校验、内嵌和缺失检测 | 已选文件 → 规范化路径到内嵌资源的映射 |
| 导出模块 | 统一文档外壳和主题、离线检查、下载 | 已排版文档模型和选项 → 完整 HTML |
| 界面状态模块 | 文件、编辑、设置、进度、预览、过期结果隔离 | 用户操作 → 只展示对应最新输入的结果 |

PDF 接口采用原始 PDF 请求体及明确的查询参数，响应 JSON：文档标题、模式、页数、内容 HTML、警告列表、页级诊断。转换器返回的 HTML 对文字和属性进行转义；不把 PDF 中的文字视为可信 HTML。

预计文件布局：`server.py`、`folio/pdf_converter.py`、`web/` 下的界面 / 转换 / 导出模块、`scripts/` 安装与资源准备脚本、`tests/`、`examples/`、`README.md`、锁定的 Python / npm 依赖清单。规格与计划保存在 `docs/superpowers/`。

## 8. 本机处理、性能与错误

服务只监听 loopback；校验 Host 与跨站请求来源，不允许任意网站调用本地转换接口。静态文件服务限制在公开资源目录，不能通过路径遍历读取用户文件。没有遥测、云端上传或持久化文档历史。

首版设置可理解的资源上限：PDF 最大 40 MiB、最多 80 页；Markdown 最大 5 MiB；关联图片总量最大 80 MiB；PDF 转换超时默认 180 秒。上限在入口和转换器中检查，超限返回可操作的错误。每次仅运行一个 PDF 转换任务；忙碌时清楚提示，避免不受控并发占用内存。

PDF 在独立进程内处理，页面按顺序渲染并及时释放资源。临时输入只存在于进程内存或专用临时目录；任务结束、异常和超时后都清理。文档和生成结果不写入服务日志。浏览器会话只在内存中保留当前文件，刷新后不承诺恢复。

首次安装依赖需要网络；依赖准备完成后的启动、转换、预览和已导出文档阅读均应能够离线进行。安装失败必须显示具体步骤和恢复方式，不能假装安装成功。

## 9. 验收与验证

1. **Markdown 语法与公式**：使用包含中英文、四种公式分隔符、AMS 对齐、矩阵、公式编号、脚注、嵌套列表、表格、代码块和图片的样例；验证公式 SVG 已生成，代码中的公式字符未被误解析，货币与转义美元可按规则显示。
2. **资源与安全边界**：检查中文与空格路径、重复图片文件名、缺失图片、恶意 HTML / SVG、危险链接与服务路径遍历；证明未执行输入脚本，未读取公开目录外的文件。
3. **PDF 实际输出**：用可复现生成的文字 / 表格 / 图片 / 数学外观 / 不同尺寸 / 旋转页面样本检查两种模式；扫描件能保真输出，阅读模式会给出回退；无效文件、超限文件和加密文件给出明确错误。
4. **离线导出**：保存 HTML 后以文件方式重新打开，在阻止网络请求的浏览器测试中验证公式、图片、主题、目录与原页折叠区可用，没有必需的外部加载或脚本错误。
5. **视觉核验**：在桌面与窄屏中检查三个主题、长公式、宽表、中文字体、PDF 页面比例和打印样式；实际截图检查，不以 DOM 断言代替排版验收。
6. **启动体验**：验证安装后的双击启动流程、端口冲突提示和健康检查；说明依赖版本、启动命令与已知限制。

验收不包含“任意 PDF 完全还原为可编辑 HTML”或“任意公式 OCR 100% 准确”。测试样本通过只说明覆盖的输入已验证，不代表所有用户 PDF 已验证。用户尚未提供真实 PDF，因此最终交付需说明真实文档效果仍应通过实际文件评估。

## 10. 最可能失败的三个点

| 失败点 | 原因与触发条件 | 缓解与可验证证据 |
| --- | --- | --- |
| PDF 重排损坏语义 | 双栏、公式字形、表格跨页和扫描件没有可靠结构 | 保真默认、页级回退、保留原页；用复杂与扫描样本验证警告和输出 |
| 导出后公式或图片缺失 | 尚未完成异步排版、引用共享 SVG 字形、相对图片路径或远程依赖 | 导出等待当前转换完成；内嵌 SVG 与图片；离线重开与零必需网络请求验证 |
| 本机安装或大文件处理失败 | Python / 原生 PDF 依赖不兼容，渲染图片占用内存，端口冲突 | 锁定已验证版本、检查环境、设置大小 / 页数 / 超时限制、隔离进程；测试错误恢复 |

## 11. 范围外与后续决策

首版不包含桌面安装包、批量队列、云部署、账号、付费服务、全文 OCR、公式 OCR、完整 TeX 编译、任意外链图片自动下载和商业字体自动嵌入。后续若用户实际文档要求这些能力，再单独评估依赖、准确率、资源与交付方式。

当前待决事项只有本规格的审阅。依赖版本、模块内实现细节和 CSS 细节属于实现阶段可以依据兼容性与验证结果自主决定的事项。

## 12. 技术依据

- [pypdf：Why Text Extraction is hard](https://pypdf.readthedocs.io/en/stable/user/extract-text.html#why-text-extraction-is-hard)：PDF 的阅读顺序、表格和扫描图像不能当作已存在的语义结构。
- [MathJax 4：Loading MathJax](https://docs.mathjax.org/en/latest/web/loading.html)：本地加载 TeX / SVG 组合组件及版本 4 的资源路径。
- [MathJax 项目](https://www.mathjax.org/)：浏览器数学排版与 SVG 输出。
- [pdfplumber 官方仓库](https://github.com/jsvine/pdfplumber)：字符位置、字体、图形与表格提取能力及限制。
- [pypdfium2 文档](https://pypdfium2.readthedocs.io/en/stable/python_api.html)：本地 PDF 渲染与资源管理接口。
