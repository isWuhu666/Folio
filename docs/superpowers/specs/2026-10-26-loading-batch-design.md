# 加载效率与批量并发设计

用户确认：同时处理多份文档，并保留每份独立结果。沿用本机浏览器与 Android 离线架构，不上传文档。

保留单篇编辑工作台，新增独立批量任务面板。主文档最多 20 份，图片按明确相对路径共用；同名输出增加序号。Windows 默认两个任务并发，手机默认一个并允许有限调整；PDF 后台最多两个独立进程，公式仍由共享 MathJax 顺序排版，避免公式编号状态交叉。并发表示独立文档流水线并行，不宣称浏览器主线程上的 Markdown 解析自动变为多核。

任务具有等待、运行、完成、需核对、失败、取消状态；独立进度、错误、下载入口；可取消单项或全部。有缺图、公式错误时需要明确确认后下载，不能用批量入口绕过既有导出检查。支持将成功且无需核对的成品打包 ZIP；可预览结果，不覆盖当前编辑文档。

限制输入与结果总字节数、并发数、任务数、图片数；结果在本次页面内保留至主动清理或刷新，重要内容下载到磁盘。Android 保存仍使用原生系统选择器，并保持原生保存串行确认。

加载优化：静态资源使用可失效的条件缓存，API 不缓存；图片读取有界并行，复用同一 File 的已校验结果；无公式文档不等待无关公式队列；Android PDF 引擎按需加载。先测基线再比较；不通过增加自动重试或放宽安全限制掩盖故障。

主要失败面：并发内存增长（总量及进程上限）、同名/路径混淆（独立名称与精确路径）、取消未清理后台任务（取消确认与进程树清理）。验证涵盖实际不同结果、并发屏障、取消、错误隔离、离线 ZIP、缓存失效，以及全部既有回归。
